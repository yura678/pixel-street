# Pixel Street — будинки: принципи й робота з ними

> Редизайн усіх 32 будинків петлі завершено 11.11.2026 (Етапи 0–14). Опис кожного будинку — його специфікація в `src/config/buildings/chunkNN.js`. Таблиця петлі, силует і знахідки — `docs/STREET_AUDIT_GENERATED.md` і `docs/STREET_ELEVATION.svg` (`npm run audit`). Цей файл — правила для нових будинків і переробок.

## Принципи

Вулиця — нескінченна петля завдовжки 240 м: затишна мініатюрна вулиця кінця XIX століття в дусі Брукліна й Мангеттена, жовте таксі, дві зупинки, провулок, сквери й ратуша. Кожна будівля — реальний архітектурний тип із логічним планом квартир, входів, вікон і даху, зібраний зі спільних деталей.

1. **Один будинок — один тип і один матеріал.** Кожен має реальний прототип із довідника стилів рядових будинків Нью-Йорка (LPC): Federal, Greek Revival, Italianate, Anglo-Italianate, Second Empire, Neo-Grec, Queen Anne, Romanesque, Renaissance і Colonial Revival. Вітрини — за NPS Preservation Brief 11. Висота, дах і ганок випливають зі стилю, а не з випадковості.
2. **Спершу план квартир, потім фасад.** Ділянка завширшки 4.8–7.5 м — це 2–3 осі. Одна вісь — одне вікно на поверх, кожне вікно належить конкретній кімнаті (`FlatPlanner`).
3. **Входи логічні.** Житловий будинок має видимий вхід: ганок або двері, номер, домофон. Будинок з крамницею має окремі двері до квартир збоку від вітрини, крамниця — свій вхід. Дверей у нікуди немає.
4. **Сходова клітка.** У багатоквартирному будинку над входом ідуть сходові вікна, зсунуті на пів поверху. В односімейному — звичайні вікна.
5. **Вікна.** Високі тайли 2:3, без розтягування. Штори й світло — по квартирах. У крамниць — просте скло без вигаданого інтер'єру, допускається напис на склі.
6. **Пожежні драбини** лише на багатоквартирних будинках від 4 поверхів, по одній на стояк, над вікнами вітальні: знизу відкидна драбина, згори «гусак» на дах. Де драбина на фасаді недоречна — на тильному боці. На фасаді вони є лише в № 114, 132, 146, 154 (бічна — № 130).
7. **Кондиціонери:** не більше одного на квартиру й не в кожній (≈ 40 %), під вікном спальні; не на сходових вікнах, не за драбинами, не на односімейних будинках.
8. **Дахи за стилем.** Пласкі з карнизом (Italianate, Neo-Grec, Renaissance, тенементи), мансарда з люкарнами (Second Empire), двосхилий з люкарнами (Federal), щипець фасадом на вулицю (Dutch), парапет (одноповерхові крамниці). На пласкому даху — парапет, люк і вентстояки. Димарі — лише де їх передбачає стиль, і лише на межовій стіні.
9. **Межові стіни.** Де будинок вищий за сусіда, він показує глуху стіну з парапетом. Вікна на бічній стіні — лише до скверу, провулка чи саду сусіда з відступом.
10. **Жодних розтягнутих текстур.** На оздобленні — `texScale`, двері — геометрією, вивіски 3:1.
11. **Жодних рослин на фасадах.** Зелень — у садах, вазонах і лише в ящиках квіткової крамниці № 108.
12. **Номери** парні, по порядку: № 100 на Z 0, далі через № 114 і раменну № 118 до № 166 (пропуск лише біля будинку на двох ділянках).
13. **Заклади.** Одна вивіска на заклад, на смузі над вітриною; типи закладів по петлі не повторюються. Лише загальні слова (BAR, HOTEL) — жодних справжніх брендів.

## Будинок як дані

Будинок — специфікація `BuildingSpec` (typedef у `src/config/buildings/index.js`; зразок — `chunk04.js`). `StreetLayout` дає ділянці поле `spec: 'noNNN'`, далі:

- `architecture/SpecPlanner.js` (без three): специфікація + ділянка → план (осі, вікна з квартирами, драбини, водостоки, входи, вітрини, пояси, межові стіни, `doorZones`); `openingsOf(plan)` — прорізи для правил;
- `architecture/Assembler.js` збирає план із деталей у фіксованому порядку (маси → пояси → карниз → дах → вікна → драбини → водостоки → входи → вітрини → ділянка). Невідомий тип даху, входу чи вітрини — помилка з назвою: деталі ще немає в бібліотеці;
- деталі — `src/world/architecture/`: `Facade`, `Windows`, `Doors`, `Stoops`, `Bays`, `Balconies`, `Storefront`, `Canopy`, `Machiya`, `Carriage`, `Stalls`, `Terrace`, `Roofs`, `Gables`, `Cornices`, `PartyWall`, `Flanks`, `Egress`, `Services`, `Civic`, `Square`, `Alley`, `Greenery`, `StreetTrees`, `primitives`, `palette`. Вітрина всіх деталей — `?debug=parts`.

## Правила (`buildings.rules.test.js`, `StreetAudit`)

- У кожного будинку з квартирами є вхід до них; у будинку з крамницею — окремі двері.
- Кондиціонерів не більше, ніж квартир; не на сходових вікнах і не за драбинами.
- Драбина лише при 4+ поверхах і кількох квартирах; її верх спирається на дах.
- Прорізи не перетинаються між собою, з поясами, дверима й вивісками і лежать у межах фасаду й нижче карниза.
- Номери парні, ростуть, не повторюються; вивіски не повторюються.
- Сусіди не мають однакового даху з однаковим карнизом; три сусіди підряд не однакові заввишки; кольори стін сусідів розрізняються (OKLab).
- Межова стіна є над кожним нижчим сусідом і відсутня над таким самим.
- Ганок не виступає за лінію дерев; бічні фасади — лише до провулка, скверу чи саду.
- Не більше 60 тис. трикутників на чанк; тайли вивісок, табличок і вікон є в атласі й не перекриваються.

## Як додати чи переробити будинок

1. До змін: `npm run geometry -- snapshot before`.
2. Специфікація — у `src/config/buildings/chunkNN.js` (+ рядок в `index.js`, `spec` на ділянці в `StreetLayout.js`). Нова деталь — у `src/world/architecture/` і гілка в `Assembler.js`; розрахунки — у `SpecPlanner.js`.
3. Нові тайли — лише у вільні клітинки атласу: `npm run geometry -- atlas`.
4. `npm test`, `npm run lint`, `npm run build`, `npm run audit`, `npm run geometry -- overlaps --chunk=N`.
5. `npm run geometry -- snapshot after` і `compare before after`: змінитися має лише цей чанк (і лінія обшивки межової стіни сусіда, якщо поруч змінився дах). `npm run geometry -- tris` — не більше 60k на чанк.
6. `node scripts/shots.js --chunk=N`, переглянути знімки (розтягнуті текстури, мерехтіння, щілини, деталі в повітрі), показати користувачу й чекати «далі».

**Будинок готовий, коли** відповідає своєму типу (поверхи, вхід, дах, квартири, кондиціонери, драбини), правила й тести зелені, на знімках з таксі, анфас, входу й увечері немає дефектів, межові стіни саме там, де сусід нижчий, чанк у бюджеті трикутників, а користувач сказав «далі».

### Пастки

- Prettier — лише на нових файлах і тих, що вже чисті (`npx prettier --check <файл>`): `PixelCanvas.js`, `BuildingFactory.js`, `StreetLayout.js` відформатовані не Prettier.
- `wood` — натуральне дерево без тонування; фарбоване — тільки `wood_paint`.
- `orientedQuad`/`orientedTri`: нормаль задаєш явно; віддзеркалити грань — переставити вершини `(p1, p0, p3, p2)`.
- Вивіски 3:1, вікна 2:3, окрема грань з тайлом — `rep: [1, 1]`; матеріали — через `texScale`.
- Дві площини в одній площині мерехтять: зсувай деталь на 3–5 мм; перевірка — `npm run geometry -- overlaps` і тест `overlaps.test.js`.
- Площина без товщини (скат, козирок) знизу зникає: обгорни її `b.mark()` … `b.backFaces(m)`.
- Сусідні карнизи на одній висоті роби на 4 см вужчими за ділянку (`colonial`).
- Заглиблені двері чи ворота ховає маса стіни: вирізай отвір (`plan.recesses` → `buildFacadeMass`, `cut: true`) і вимикай плінт (`wall.plinth: false`), якщо вітрина облицьована до тротуару.
- PowerShell з'їдає `--`: викликай `node scripts/shots.js --chunk=8` напряму, а `--cam=…` бери в лапки.
- `shots.js --cam=z,look,zoom,az,el`: для крупного плану входу `zoom` 0.25. Вечірній знімок інколи виходить зі старту таксі — перезніми `--only=noNNN --views=evening`.
- Знімки без відеокарти (SwiftShader) — з `--webgl`: скрипт підміняє `navigator.gpu`, код проєкту не змінюється.
